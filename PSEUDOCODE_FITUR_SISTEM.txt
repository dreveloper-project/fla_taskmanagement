PSEUDOCODE FITUR SISTEM PT Flores Lautan Abadi
Berdasarkan implementasi proyek pada 10 Oktober 2026.
Termasuk Surat Laut / Pas Besar / Pas Kecil, Task Monitoring, Reports,
pengarsipan layanan/dokumen, serta sistem dua level pengguna Admin dan Staff.
Mencakup sinkronisasi PIC layanan/task otomatis, halaman tambah/edit Vessel,
validasi file frontend, popup notifikasi animasi, ekspor XLSX, dan tombol password.

NOTASI DAN CAKUPAN
Role pengguna: admin dan staff; status akun: active dan inactive.
Admin dan Staff memakai workflow bisnis yang sama; Admin tidak bypass readiness.
Staff hanya boleh mengerjakan layanan dengan assigned_staff_id/PIC dirinya.
Staff hanya boleh mengerjakan task dengan assigned_to dirinya.
Reassignment mencabut izin petugas lama, termasuk pada form yang sudah terbuka.
INPUT: masukan pengguna. OUTPUT: hasil operasi.
JIKA/SELAIN ITU: percabangan. UNTUK: perulangan.
VALIDASI/PASTIKAN: hentikan aksi dengan pesan jika syarat gagal.
TRANSAKSI: perubahan database dilakukan bersama; gagal berarti rollback.
Nilai status menggunakan nama yang disimpan di database.
Waktu layanan mengikuti konfigurasi Asia/Makassar dan datetime disimpan UTC.
Status kedaluwarsa master dokumen menggunakan timezone aplikasi (saat ini UTC).
Pengajuan dan hasil instansi dicatat manual; tidak ada API otoritas.
Task Monitoring berbasis database dan terhubung ke kelima workflow layanan.
Status/progress Task terpisah dari status Service dan tidak mengubah status layanan.
Penggantian PIC task otomatis aktif oleh Admin juga memperbarui PIC layanan terkait.
Penugasan task manual tetap terpisah dari PIC layanan.
Reports membaca data operasional; tidak membuat tabel salinan laporan.
Ekspor laporan memakai file XLSX; seluruh hasil filter disertakan tanpa batas paginator.
Input file diperiksa di frontend sebelum upload; validasi backend tetap wajib.
Pesan error tetap berada di atas form dan dilengkapi popup notifikasi bersama.
Setiap field password memiliki tombol tampilkan/sembunyikan dengan state terpisah.
Arsip layanan bersifat logis melalui archived_at; berkas tetap di storage privat.

01. AKSES DAN AUTENTIKASI
======================================================================
PROSEDUR AKSES_OPERASIONAL(pengguna)
    JIKA belum login: arahkan ke login
    Middleware web memastikan akun yang login masih active
    JIKA inactive: logout; invalidasi session; regenerasi token CSRF
        Arahkan ke login dengan pesan "Akun tidak aktif. Hubungi Admin."
    Gate access-system mengizinkan hanya active admin atau active staff
    Gate access-admin mengizinkan hanya active admin
    Route operasional memakai auth dan access-system
    Route Staff Management juga memakai access-admin; Staff ditolak 403
    Pemeriksaan berlaku pada request HTTP dan pembaruan Livewire
    Tampilkan halaman jika seluruh pemeriksaan sesuai
SELESAI

PROSEDUR HALAMAN_REGISTRASI_PERTAMA
    GET /register hanya tersedia untuk guest saat users masih kosong
    Jika sudah ada satu pengguna, termasuk inactive: arahkan ke login
    Form tidak menyediakan pilihan role/status
    Halaman login menampilkan tautan Buat Admin pertama hanya jika users kosong
        Selain itu tampilkan arahan menghubungi Admin untuk akun Staff
SELESAI

PROSEDUR REGISTRASI(input, foto_opsional)
    Batasi registrasi 5 permintaan per menit per IP
    FormRequest menolak POST dengan 403 jika users sudah berisi
    Trim dan ubah username/email menjadi huruf kecil
    Validasi nama, username unik, email unik, password dan konfirmasi
    Telepon dan foto opsional; username 3-50 karakter, huruf kecil/angka/titik/garis bawah
    Foto: JPG/JPEG/PNG/WebP, maksimum 2 MB, dimensi maksimum 4096 x 4096
    Password mengikuti kebijakan aplikasi; produksi minimum 12 karakter,
        huruf besar/kecil, angka, simbol, dan pemeriksaan kebocoran
    Simpan foto ke storage privat bila ada
    Gunakan cache store database yang mendukung atomic lock
    Ambil lock initial-admin-registration: masa lock 120 detik; tunggu maksimum 5 detik
        MULAI TRANSAKSI
            Cek kembali User.exists() di dalam lock
            Jika sudah ada pengguna: tolak 403 tanpa membuat akun kedua
            Buat pengguna dari identitas tervalidasi; password di-hash oleh model
            Backend menetapkan role = admin dan status = active
            Abaikan role/status serta atribut istimewa dari request
            Simpan pengguna; commit
        Lepaskan lock otomatis setelah callback berakhir
    Jika gagal: rollback bila perlu; hapus foto baru
        Jika lock timeout: tampilkan pesan registrasi awal sedang diproses
        Selain itu: teruskan kesalahan
    Kirim event Registered; login otomatis; regenerasi session; arahkan ke Overview
    Flash auth_status <- "Akun berhasil dibuat. Selamat datang."
    Tampilkan popup sukses pada halaman tujuan
    Semua akun Staff berikutnya dibuat melalui Admin, tanpa registrasi publik
SELESAI

PROSEDUR LOGIN(username, password, remember, IP)
    Normalisasi username; validasi input
    kunci_limit <- hash(username + IP)
    JIKA sudah 5 kegagalan dan limit masih aktif: tampilkan waktu tunggu
    Coba autentikasi username/password dengan role admin atau staff
    Setelah kredensial benar, callback attemptWhen memeriksa status active
        Inactive tidak menghasilkan login berhasil atau session login baru
    JIKA gagal: tambah hit limit selama 60 detik
        Kredensial benar tetapi inactive -> pesan akun tidak aktif
        Selain itu -> pesan username atau password salah
    JIKA berhasil: terapkan remember; bersihkan limit; regenerasi session
        Arahkan ke tujuan sebelumnya atau Overview
        Flash auth_status <- "Login berhasil. Selamat datang kembali."
        Tampilkan popup sukses pada halaman tujuan
SELESAI

PROSEDUR LOGOUT
    Logout; invalidasi session; regenerasi token CSRF; arahkan ke login
    Flash auth_status <- "Anda berhasil logout."; tampilkan popup sukses
SELESAI

PROSEDUR TAMPILKAN_FIELD_PASSWORD(field)
    Berlaku pada login, registrasi, ubah password, dan tambah Staff
        Termasuk password saat ini, password baru, dan konfirmasi password
    Gunakan komponen password-field; nilai awal passwordVisible <- false
    Render input dengan type password dan ruang untuk tombol ikon mata di kanan
    Tombol bertipe button agar klik tidak mengirim form
    Saat tombol diklik: passwordVisible <- NOT passwordVisible
        Jika true: type input <- text; ikon mata dicoret; label Sembunyikan password
        Jika false: type input <- password; ikon mata; label Tampilkan password
    Perbarui title, aria-label, aria-pressed, dan aria-controls untuk field terkait
    State setiap field terpisah; perubahan hanya memengaruhi tampilan input
    Pertahankan autocomplete, required, validasi, serta binding Livewire yang ada
    Input password tidak diisi ulang dari old input setelah validasi gagal
SELESAI

05. STATUS DOKUMEN, VERSI, DAN CREATE SERVICE
======================================================================
FUNGSI STATUS_DOKUMEN(expired_date)
    Jika NULL: unknown
    hari_ini <- tanggal pada timezone aplikasi
    Jika expired_date < hari_ini: expired
    Jika expired_date <= hari_ini + warning_days: expiring_soon
    Selain itu: valid
SELESAI
Konfigurasi warning_days saat ini 30 hari, termasuk batas hari ke-30.

FUNGSI KONDISI_DOKUMEN_KAPAL(dokumen)
    Jika kosong: No document uploaded
    Hitung tiap status; prioritaskan ringkasan expired dan expiring_soon
    Jika keduanya tidak ada tetapi unknown ada: masa berlaku belum diketahui
    Selain itu: All Documents Valid
SELESAI

PROSEDUR ARSIPKAN_VERSI(dokumen, petugas)
    Salin nomor, path, nama file, tanggal dan sumber layanan
        ke VesselDocumentVersion
    Simpan status=superseded, archived_at dan archived_by
    Pertahankan file lama agar tetap dapat diunduh
SELESAI

FUNGSI LINK_CREATE_SERVICE(dokumen)
    Hanya lanjut jika expired/expiring_soon dan jenis mempunyai mapping
    safety_certificate -> safety-certificates.create, hanya kapal passenger
    surat_laut/pas_besar/pas_kecil -> ship-nationality.create
    sijil_awak_kapal -> sijil.create
    Sertakan vessel_id, client_id, document_type, document_id, service_type
    Untuk keselamatan/kebangsaan: request_type=renewal, previous_document_id
    Jika route belum tersedia: tidak ada link
SELESAI

07. SPB / SURAT PERSETUJUAN BERLAYAR
======================================================================
PROSEDUR DRAFT_SPB
    Validasi Vessel, PIC staff, prioritas, total kru, pelabuhan, tujuan,
        estimasi keberangkatan dan selesai kegiatan pelabuhan
    Selesai kegiatan tidak boleh sesudah estimasi keberangkatan
    Client mengikuti Vessel; jika Vessel tanpa Client, input Client wajib
    Kapal passenger wajib total_passengers; selain itu kosong menjadi 0
    carrying_cargo wajib deskripsi; tanpa muatan kosongkan rincian muatan
    Existing hanya draft/revision_required; Vessel tidak dapat diganti
    Simpan nomor SPB, lampiran, history; kosongkan revision_ready_at
SELESAI

FUNGSI READINESS_SPB
    Wajib spb_request_letter, master_sailing_declaration, crew_list,
        warta_kapal, payment_proof, pnbp_proof
    Jika passenger ATAU total_passengers > 0: wajib passenger_manifest
    Jika carrying_cargo: wajib cargo_manifest dan deskripsi
    Jika port_cargo_activity_applicable: wajib rkbm dan pbm
    Semua file wajib harus tersedia di storage
    Dokumen Vessel wajib: Surat Ukur; Surat Laut/Pas Besar/Pas Kecil;
        Safety Certificate; Safe Manning; Classification Certificate
    tanggal_acuan <- maksimum(hari ini WITA, estimasi berangkat WITA)
    Dokumen harus berlaku sampai tanggal_acuan
    Keselamatan, Safe Manning dan Classification wajib expired_date
    Kembalikan complete dan daftar kekurangan
SELESAI

PROSEDUR SIAPKAN_SPB
    Izinkan draft/revision_required; readiness harus lengkap
    draft -> ready_to_apply
    revision_required -> isi revision_ready_at, status tetap revisi
    Catat history
SELESAI

PROSEDUR AJUKAN_SPB(tanggal, referensi)
    Izinkan ready_to_apply/revision_required
    Revisi wajib revision_ready_at; periksa ulang readiness
    Tanggal bukan masa depan dan tidak sebelum pengajuan sebelumnya
    Salin referensi dokumen Vessel; simpan submitted_at atau resubmitted_at
    status <- applied; kosongkan revision_ready_at; catat history
SELESAI

PROSEDUR HASIL_SPB(hasil)
    Pastikan status applied
    revision_required: wajib catatan/item revisi; lampiran opsional
        status <- revision_required; kosongkan revision_ready_at
    rejected: wajib alasan; lampiran opsional; status rejected dan arsip logical
    approved: wajib nomor, tanggal terbit, file issued_spb
        Terbit tidak sebelum pengajuan terakhir atau di masa depan
        Tolak jika kapal punya SPB lain ready_to_sail/sailing
        status <- ready_to_sail; kapal belum otomatis berlayar
    Catat history
SELESAI

PROSEDUR KONFIRMASI_BERANGKAT_DARI_VESSEL(spb, waktu)
    SPB harus milik Vessel yang dipilih, ready_to_sail, belum dikonfirmasi
    Kapal harus berthed; file issued_spb harus tersedia
    Waktu tidak sebelum SPB terbit dan tidak di masa depan
    Vessel <- sailing; isi sailed_at dan petugas
    SPB <- sailing; isi actual_departure_at dan petugas; catat history
SELESAI

PROSEDUR HASIL_PELAYARAN(hasil, alasan)
    Izinkan ready_to_sail/sailing
    success: keberangkatan wajib sudah dikonfirmasi; status <- completed
    failed: alasan wajib; status <- failed_to_sail; lampiran opsional
        Jika kapal sudah berangkat: kembalikan Vessel ke berthed
    Isi completed_at, archived_at, petugas; catat history
SELESAI

08. SERTIFIKAT KESELAMATAN KAPAL PENUMPANG
======================================================================
PROSEDUR DRAFT_KESELAMATAN
    Validasi Vessel passenger, request new_issue/renewal, prioritas, PIC staff
    Target/catatan opsional; nomor SKK; simpan lampiran dan history
    Existing hanya draft/revision_required; Vessel tetap
    Request Type tetap sesudah pengajuan
    Tangkap snapshot sertifikat lama dan salinan file bila tersedia
SELESAI

FUNGSI READINESS_KESELAMATAN
    Kapal passenger; request valid
    Wajib Surat Ukur, Surat Laut/Pas Besar/Pas Kecil, General Arrangement
    Wajib application_letter dan technical_attachment
    Renewal wajib file sertifikat lama dari referensi atau master Vessel
    Persyaratan lainnya mengikuti config; kembalikan complete dan missing
SELESAI

PROSEDUR ALUR_KESELAMATAN
    draft + readiness lengkap -> ready_to_apply
    ready_to_apply/revision_required + readiness lengkap -> under_review
        Validasi kronologi pengajuan; snapshot dokumen; catat referensi/instansi
    under_review/waiting_for_issuance dapat tetap under_review,
        revision_required (catatan wajib), atau rejected (alasan dan arsip)
    inspection_required -> jalankan penjadwalan inspeksi
    approved -> jalankan penerbitan sertifikat
SELESAI

PROSEDUR INSPEKSI
    Penjadwalan diizinkan pada under_review/inspection_scheduled
    Jadwal/lokasi wajib; jadwal tidak sebelum pengajuan terakhir
    Simpan pemeriksa/catatan; reset hasil; status <- inspection_scheduled
    Untuk mencatat hasil: status harus inspection_scheduled
    Waktu hasil tidak sebelum jadwal atau di masa depan
    Revisi wajib temuan/catatan; ditolak wajib alasan; laporan opsional
    Catat inspection_completed, kemudian:
        passed -> waiting_for_issuance
        awaiting_decision -> under_review
        revision_required -> revision_required
        rejected -> rejected dan arsip logical
SELESAI

PROSEDUR TERBITKAN_SERTIFIKAT
    Izinkan under_review/waiting_for_issuance
    Nomor, tanggal terbit, file resmi wajib
    Expired Date wajib sesuai config dan harus sesudah tanggal terbit
    Tanggal terbit tidak sebelum pengajuan terakhir atau di masa depan
    Tolak jika path sertifikat master berbeda dari snapshot awal
    Simpan file layanan; arsipkan versi master lama bila ada
    Salin hasil ke VesselDocument safety_certificate; simpan sumber layanan
    Catat certificate_issued kemudian ready_for_handover dalam satu transaksi
SELESAI

PROSEDUR HANDOVER_KESELAMATAN
    Status ready_for_handover; penerima/waktu wajib; jabatan/bukti opsional
    File resmi/master harus tersedia dan master masih bersumber dari layanan
    Waktu tidak sebelum terbit atau di masa depan
    Simpan serah terima/petugas; isi completed_at dan archived_at
    status <- completed; catat history
SELESAI
